# Messain

A simple, modern messaging application. Register, log in, and exchange persistent,
real-time messages through a clean dark-themed chat interface. Runs locally with a
single command.

![Tech](https://img.shields.io/badge/FastAPI%20%2B%20SQLite%20%2B%20React%20%2B%20Vite-backend%20%2B%20frontend-4f46e5)

## Features

- **Accounts** — register and log in with a username and password (PBKDF2-hashed, never stored in plaintext).
- **User directory** — see everyone who is registered, with live online/offline status.
- **Conversations** — start 1:1 chats; they appear instantly in the other person's sidebar.
- **Delete conversations** — the trash icon on a chat permanently deletes the conversation and all of its messages, for both participants. Start a fresh chat with the same person anytime from “People”.
- **Real-time messaging** — messages arrive over a WebSocket without refreshing, with a polling fallback.
- **Message history** — messages are stored in SQLite and reloaded when you reopen a conversation, with "Load earlier messages" pagination.
- **Read receipts** — your sent messages show a checkmark that turns into **✓✓ Read** the moment the other person opens the conversation.
- **Timestamps** — every message shows its time; the list is grouped by day.
- **Dark, responsive UI** — Discord/WhatsApp-inspired layout, sidebar + chat pane, mobile-friendly.
- **Secure by default** — validated input, participant-only conversation access, authenticated WebSocket, parameterized SQL.

## Quick start (development)

Run the backend and frontend in two separate terminals, both from the project root.

**Terminal 1 — backend** (PowerShell):

```powershell
python -m venv .venv
& .venv\Scripts\pip install -r requirements.txt
& .venv\Scripts\python -m uvicorn app.main:app --reload
```

Bash equivalent:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --reload
```

**Terminal 2 — frontend**:

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173** (the Vite dev server proxies `/api`, including WebSockets, to port 8000).

### Try it out

1. Register an account (e.g. `alice` / `password123`).
2. Open a second browser window — use a private/incognito window or a different browser
   (two tabs of the same browser share one login) — and register `bob`.
3. In Alice's window, click **bob** under "People" to start a conversation and send a message.
4. Watch it appear instantly in Bob's window, reply, and see it appear live in Alice's window.
5. Watch the ✓ next to your own messages flip to **✓✓ Read** the moment Bob opens the conversation.
6. Click the **trash icon** on a conversation to permanently delete it — for both participants —
   then start a brand-new chat with the same person from "People" anytime.

## Production-style mode (single server)

Build the frontend once, then uvicorn serves both the API and the UI on port 8000:

```powershell
cd frontend
npm run build
cd ..
& .venv\Scripts\python -m uvicorn app.main:app
```

Bash equivalent:

```bash
cd frontend && npm run build && cd ..
.venv/bin/python -m uvicorn app.main:app
```

Open **http://127.0.0.1:8000**.

## Configuration

Copy `.env.example` to `.env` to override defaults. All values are optional.

| Variable                   | Default              | Purpose                                    |
| -------------------------- | -------------------- | ------------------------------------------ |
| `MESSAIN_DATABASE`         | `data/messenger.db`  | SQLite database file path                 |
| `MESSAIN_TOKEN_EXPIRE_DAYS`| `30`                 | Days before a login token expires          |

No secrets are required at runtime: tokens are random values generated by the server.

To reset all data, stop the server and delete the database file (plus its `-wal`/`-shm` siblings).

## API overview

| Method   | Path                                       | Description                              |
| -------- | ------------------------------------------ | ---------------------------------------- |
| `POST`   | `/api/auth/register`                       | Create an account, returns token + user |
| `POST`   | `/api/auth/login`                          | Log in, returns token + user            |
| `POST`   | `/api/auth/logout`                         | Invalidate the current token            |
| `GET`    | `/api/users/me`                            | Current user                            |
| `GET`    | `/api/users`                               | All other users, with online status     |
| `GET`    | `/api/conversations`                       | Sidebar list, sorted by activity        |
| `POST`   | `/api/conversations`                       | Find-or-create a chat with a user       |
| `DELETE` | `/api/conversations/{id}`                  | Permanently delete the chat + messages  |
| `GET`    | `/api/conversations/{id}/messages`         | History (`before_id`/`after_id`/`limit`) |
| `POST`   | `/api/conversations/{id}/messages`         | Send a message                          |
| `POST`   | `/api/conversations/{id}/read`             | Mark the conversation as read           |
| `WS`     | `/api/ws?token=...`                        | Live events (see below)                 |

All authenticated routes expect `Authorization: Bearer <token>`. The WebSocket closes
with code `4401` for invalid tokens.

**WebSocket events (server → client):**

```jsonc
{ "type": "message",     "conversation_id": 1, "message": { /* MessageOut */ } }
{ "type": "presence",    "user_id": 2, "online": true }
{ "type": "conversation","conversation": { /* ConversationOut */ } }
{ "type": "conversation_removed", "conversation_id": 1 }
{ "type": "read",         "conversation_id": 1, "reader_id": 2, "last_read_message_id": 7 }
{ "type": "user",        "user": { /* UserOut */ } }
```

## Security notes

- Passwords are hashed with PBKDF2-HMAC-SHA256 (600k iterations, per-user salt); plaintext is never stored or logged.
- Login timing is equalised for unknown usernames to avoid account enumeration.
- All SQL uses parameterized statements; no user input is ever interpolated into queries.
- Conversation reads and writes are limited to participants (403 otherwise); message content is stripped and length-checked server-side.
- The WebSocket authenticates with the same token store; if the token is invalid it is closed immediately.
- Tokens live only in the database and the client's `localStorage`; the client's WebSocket falls back to polling if the live connection drops.
